# S3 交易税超过 5% 或买卖税不对称

状态：在用

## 规则

买税或卖税任一超过 5%，或者两边都能解析且绝对差超过 2 个百分点，记为「交易税超过风险门槛」。

深审要求买税、卖税都已知，并且同时满足上述两条。Solana 在二次核对里把买卖税字段置空，因为这条链的 MEME 通常不靠合约买卖税抽成。

## 来源

仓库内来源，没有附带外部回测。

- `maxBuyTax = 0.05`、`maxSellTax = 0.05`、`maxTaxAsymmetry = 0.02` 从 v0.1.6（`5784d8e`）起就在 `src/config.mjs`。
- 发现入口执行点：`src/scoring.mjs` 的 `knownRiskReasons`。深审执行点：`deepScreen` 的 `checks.tax`。
- Solana 税字段：`src/secondary.mjs` 在 `chain === 'sol'` 时把 `buyTax` / `sellTax` 设为 `null`。
- 行为锁定：`test/risk-filters.test.mjs` 用买税 10%、卖税 15% 断言发现失败。
- 对外说明：根目录 `README.md`「发现初选」。

这是 EVM MEME（BSC、Base、以太坊）貔貅和税率盘的经典门槛：高卖税、买卖税不一致，用来阻止卖出或只在买入时抽成。阈值是习惯值，不是本仓库拟合的。

## 运行范围

热榜给出税率时，默认快速扫描会执行。未知税率不会被快速路径假装成 0；深审缺税率则不放行。Solana 快速路径通常看不到这条规则，因为上游不提供 EVM 式买卖税。

## 时效

在仍能改税、能限制卖出的 EVM 合约上，这条规则继续有效，而且应当保留。高税和税差是合约级风险，不随叙事轮动过期。

它不再覆盖 2026 年 MEME 成交的主体。Pump.fun 曲线收取的是协议交易费（文档写明曲线总费约 1.25%，在创建者与协议之间拆分），不是代币合约里的买卖税。用 5% 合约税去筛 Solana 热榜，区分度接近于零：绝大多数样本都会「通过」，而捆绑、曲线形状和毕业抛压完全看不见。

## 可考虑的后续策略

尚未实现。EVM 上不建议放宽 5% / 2 个百分点，除非另有样本证明误杀。

- 按链拆开：EVM 继续用税率和卖出限制；Solana 改看铸币权、冻结权（深审已要求两者放弃）以及捆绑、狙击持仓。
- 把「貔貅 / 不能全部卖出」继续当作硬事实。`aveDiscoveryScreen` 已经会拒绝 `is_honeypot`、`sellable === false` 和 `cannot_sell_all`。这和税率是相邻规则，值得另开一条 S7，而不是并进 S3。
