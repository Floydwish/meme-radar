# S2 DEV 持仓超过 1%

状态：在用

## 规则

`dev_team_hold_rate`、`creator_balance_rate` 或 `creator_hold_rate` 中能解析出的持仓比例若大于 1%，记为「DEV持仓超过1%」，不进入候选。

「已卖出」或创建者关闭仓位的标签不能把正的持仓数字改成零，也不能把缺失持仓补成零。缺失持仓在深审里是未知字段，不会被算成已通过。

## 来源

仓库内来源，没有附带外部回测。

- 硬门槛写于 `21118ea`（2026-09-19，`feat: add voice alerts and strengthen scam-risk filters`）。在此之前，深审把创建者已平仓当成 DEV 检查通过；这次提交改成必须看到不超过 1% 的持仓数字。
- 执行点：`src/scoring.mjs` 的 `knownRiskReasons`（`dev > .01`）和 `deepScreen` 的 `checks.dev`（`devHold <= 0.01`）。
- 行为锁定：`test/risk-filters.test.mjs`「DEV exit labels cannot override positive holdings or fill a missing balance」，样例持仓 8.03%。
- 对外说明：根目录 `README.md`「发现初选」。

1% 是 GMGN 时代「部署者几乎已退出」的安全偏好，用来减少部署者钱包直接砸盘。它不是从本仓库的影子样本里拟合出来的。

## 运行范围

热榜行里已经带有 DEV 持仓时，默认快速扫描会执行。字段缺失时，快速发现不会仅凭这一项排除，深审则会因未知而不放行。

## 时效

部署者（或同一资金簇）仍握有可立即卖出的大比例筹码，这个风险还在。过时的是「大于 1% 即排除」这一刀。

2026 年公开的 Pump.fun 检查清单把危险线放在大约 10% 的部署者持仓，或部署者加上少量狙击钱包合计超过约 35%。联合曲线创建者还参与交易费分成，完全退出不再是唯一的「安全」形态。与此同时，真正的抛压经常不在标签为 dev 的那一个地址上，而在同一区块里用 Jito bundle 买进的一串新钱包。只卡 1% 的单地址，会放过捆绑簇，也会把仍留少量筹码、但筹码已分散的盘全部挡在外面。

本仓库深审里已有更接近当前盘面的字段，只是不属于这六条、而且默认快速扫描不逐币深审：`maxBundlerRate = 0.15`、`maxSniperHoldRate = 0.08`、`maxTop10Rate = 0.30`，以及创建者历史发币次数、毕业比例、删帖比例等降级信号（`marketBehaviorScreen`）。
