# Meme 雷达：边学边验证的执行计划

## 一句话方向

先把本仓库当成**只读的候选观察与学习工具**，学会解释每条提示及其未知项；再记录完整样本，检验筛选是否改善判断。它不是自动赚钱工具，本计划不包括买币、自动交易或提高提醒等级。

## 为什么先这样做

当前雷达从有限的 AVE 热榜数据发现线索，默认快速扫描不逐币完成深审；已有影子表现可以查看，但默认模式不会自动新增或回补样本。出现在线索列表、显示涨幅，都不等于安全、可成交或有净利润。在尚不熟悉池子、流动性、持仓、发行阶段和滑点时，直接叠加策略更容易把字段当成结论。

## 现在的下一步：建立候选研究卡

先审计现有导出、筛选记录与影子结果：哪些字段和时间戳确实留存，哪些通过、拒绝、未知、失败样本会丢失；形成字段清单与缺口清单。然后做最小的只读记录/导出改动，不先增加选币规则或昂贵数据接口。

建议研究卡至少能回答：

| 问题 | 当时要留下的证据 | 不可误读为 |
|---|---|---|
| 它是什么？ | 链、合约地址、池地址、发现/来源时间 | 首次上榜就是刚发行 |
| 为什么出现？ | 规则版本、触发字段、数值、数据来源与采样时间 | 筛选通过就是安全 |
| 哪些风险已知或未知？ | 已知风险、缺失/过期字段、来源冲突、人工核对记录 | 未知就是通过 |
| 能否退出？ | 当时流动性、池深度/卖出限制的已知证据与缺口 | 报价或纸面涨幅就是成交收益 |
| 后来怎样？ | 固定观察窗口的结果、实际采样时间、缺失/消失/失败原因 | 事后价格能填回发现时点 |

先选**一条当前支持的链**，按固定规则连续观察约 **20–30 条**线索，包含不好看的案例。这个数量只是练习研究卡和发现记录缺口，**不是证明策略有效的统计门槛**。学习顺序随真实案例走：合约与池 → 流动性和卖出 → 持仓/权限 → 发行阶段 → 价格与成交 → 成本和滑点；每个概念都对应研究卡的一个判断或未知项。

## 后续阶段与验收

1. **看懂线索。** 交付简短术语表和 20–30 张研究卡。验收：能够说明一条提示为何出现、什么尚未核验、可能如何亏损。
2. **补齐观察闭环。** 固定单链、规则版本、入样方式与后续窗口；保留通过、拒绝、未知、消失、数据失败样本。验收：能重建发现当时所见，不用未来信息修饰旧判断；报告覆盖率和缺失率。
3. **检验一个具体问题。** 根据记录中最常见的失误，只选一项可证伪假设（例如流动性不足是否应更早排除），与简单基线按时间顺序比较。验收：报告改进及反例、样本范围、成本和退出假设；失败就撤回或调整假设。
4. **按需扩展。** 只有已记录的失败类型需要时，才考虑发行阶段、交易级活动、钱包或社交数据；先评估数据质量、API 成本及维护负担。
5. **另行讨论实盘。** 纸面观察不能代表实际成交；任何真实资金试验、交易接入或自动化都需要独立的风险审查和明确授权，不由本计划自动推进。

每阶段先核对实际结果，再决定是否进入下一阶段。若数据不足或无法验证退出路径，应保持“未知/未验证”，不通过降低标准来制造结论。更详细的策略假设与证据边界见 [Meme 币策略研究路线](MEME-STRATEGIES.md)。
